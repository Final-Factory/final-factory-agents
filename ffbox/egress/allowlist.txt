# ffbox egress allowlist — the ONLY hostnames a run may reach.
#
# One name per line. A bare name matches exactly; a leading "*." matches any subdomain of it
# (and not the bare domain — list that separately if it is needed). Blank lines and # comments
# are ignored. Anything absent from this file is refused at the SNI, with the attempt logged.
#
# HOW TO ADD SOMETHING. Do not guess. Put the proxy in log mode for a few real runs —
#     sudo systemctl stop ffbox-egress
#     FFBOX_EGRESS_MODE=log ffbox/egress/ffbox-egress.sh up
# — which permits everything and records every destination, then read the SNIs back out:
#     ffbox/egress/ffbox-egress.sh log
# Add what the runs actually asked for, restart in enforce mode, and confirm nothing new appears.
#
# The container runs `claude -p`, so the model's own endpoint has to be here. There is no
# version of this file that is Unity alone and still does any work. See
# docs/docker-security-model.md, "What the allowlist cannot do", for what remains reachable
# through the entries below.

# --- Anthropic ---------------------------------------------------------------------------------
# api.anthropic.com carries the model traffic, feature flags and telemetry logging.
# platform.claude.com is OAuth token exchange and refresh: CLAUDE_CODE_OAUTH_TOKEN is long-lived,
# so this is here for the refresh path rather than for every run.
api.anthropic.com
platform.claude.com

# Deliberately ABSENT, and the container's environment is what keeps them absent rather than

# --- Unity Package Manager ---------------------------------------------------------------------
# A run restores Library/ from the ffcache entry, so UPM should resolve from that and never come
# here. It is listed because the cost of being wrong is a failed verification at the END of a run,
# after the agent has done all of its work.
#
# THE CACHE BEING RIGHT IS NOT ENOUGH, which is what 2026-08-31 cost us. Conversation 30's harness
# verification died at `unity exit 1 after 7s` on ten packages, every one of them present in
# develop@6000.3.19f1.tar at exactly the version packages-lock.json asks for -- entities at 1.4.7
# with 5082 members extracted. UPM went to the registry anyway, and being refused there turned a
# slow resolve into a failed run. Why it re-resolves packages it already has is still open.
#
# download.packages.unity.com IS THE ONE THIS LANE KEPT MISSING. The CI lane hit the identical
# refusal on 2026-08-29 and added it (runners/egress/allowlist.txt); that entry even predicted
# this one -- "a cold UPM resolve in a real import is exactly where it would be" -- and it was
# never carried across. It is also the worked example of the second refusal path in
# docs/egress.md: the bare `packages.unity.com` below lets dnsmasq resolve the subdomain by
# suffix, so the connection reaches nginx, whose match is EXACT, and dies in the deny sink. What
# the run sees is ECONNRESET and a message about its own firewall, which is us.
packages.unity.com
cdn.packages.unity.com
download.packages.unity.com
