# Project memory: Testing & tooling gotchas

Part of the `project-memory` skill; links are relative to the skill directory. Add new
entries for this area here, one line each.

- [Native build success with errors](memories/build-report-success-with-errors.md) — require a zero-error BuildReport, C#/Burst checks, baked SubScene files, and real startup; CleanBuildCache recovered an observed missing-scene build
- [A removed wait moves to the next system](memories/heartbeat-perf-a-removed-wait-moves-to-the-next-system.md) — on big saves most fixed-group main-thread time is `JobHandle.Complete` on serial job chains; moving one main-thread read into a job drops that system to ~0 and the next system pays the wait (CometSpawner 4.8 ms → AncientPortalCollision); judge a perf change by the whole-heartbeat A/B (`-ffBenchSystems`, `ab_summary.py`)
- [Judge build-vs-build performance side by side on BEAST](memories/beast-shared-machine-perf-ab-side-by-side.md) — other sandboxes' editors and GPU benches slowed a headless host from 3.3 ms to 90-260 ms a frame with total CPU ~30 %; one-after-the-other A/B looked like a regression, the two builds' pairs run at the same time paced the same
- [FMOD startup assert kills a headless client](memories/fmod-init-assert-kills-headless-client.md) — `'gSystemInitCount == 0' failed`, then silence; the audit says `missing report(s) host='none' client='none'`; ~2 in 15 launches on two builds, a re-run passes
- [Sandbox player builds: lost edits, pausing for a quiet window, localhost client identity](memories/sandbox-player-build-reverts-tracked-edits-and-quiet-window-suspend.md) — `build_player.sh` reverts every tracked edit made while it runs; a batchmode build cannot be killed by hand, so suspend and resume its process tree; a crawling Burst step still finishes; `-ffAutomationReclaimIdentity` per localhost client
- [Keep a sandbox branch pushable after a rebase, without force](memories/sandbox-branch-after-rebase-without-force.md) — push a tree-equal `git commit-tree HEAD^{tree} -p HEAD -p origin/<branch>` merge to the branch ref, develop gets the linear commits; remap pre-rebase hashes in proofs; `git add <dir>` sweeps other agents' untracked files, so stage explicit paths
- [Baseline before lifecycle tests](memories/live-baseline-before-lifecycle.md) — preserve both paired reports before reconnect, and verify temporal capture framing
- [Mirror implementations need a golden fixture](memories/mirror-implementation-golden-fixture.md) — a report-only set (or any logic) reimplemented in more than one language (C#/shell/python) drifts silently without a shared golden fixture pinned in every mirror, plus a test that they agree
- [Hand-rolled test double must mirror or say so](memories/hand-rolled-test-double-must-mirror-or-say-so.md) — a test double that deliberately reproduces a production shape (055 R37 KnnLateSpawnTransformPassWitnessTest mirroring AttackingShipSpawnerSystem) must name the real-system test covering the actual code path, or the mirror can go vacuous silently when either side changes
- [`cmd | tee log || true` clobbers PIPESTATUS](memories/shell-tee-pipestatus.md) — the exit code is always 0 regardless of `cmd`'s real result; use `set +e`/`set -e` around the pipe instead
- [Long tool sessions and archive verification](memories/tool-session-polling-and-archive-verification.md) — forward nested terminal results to expose `session_id`, poll with `write_stdin`, and treat outer-cell output as non-verdict; archive proof compares independently regenerated raw-tar hashes plus full inventories and manifests
- [Guard tests follow the landed fix, not the proposed one](memories/guard-tests-follow-the-landed-fix-not-the-proposed-one.md) — a guard written alongside a proposed fix design encodes that design's invariant (055 R37: a writer-side guard would have failed the reader-side fix that actually landed at `7304103d6`); re-derive from what shipped, and treat a census guard's unreviewed count as the deliverable to adjudicate, not noise to silence
- [Actual-system handoff tests follow source group order](memories/actual-system-handoff-test-order.md) — when a handoff crosses fixed groups, preseed the prior actual state, drive the real handoff/playback, and observe before the next producer pass; never insert an impossible producer pass to satisfy an assertion
- [EnterWorktree cuts from master, not develop](memories/enterworktree-cuts-from-master-not-develop.md) — the default `worktree.baseRef=fresh` branches from `origin/master`, but Final Factory integrates on `develop`, so a fresh worktree is missing every in-flight spec's files; first command in any new worktree is `git reset --hard origin/develop`, verified with `git log -1`
- [Audit fixtures and report grounding](memories/audit-fixture-and-report-grounding.md) — source-count agreement never replaces the full fingerprint comparator; a join fixture must create construction tasks before asserting its witness; inspect baked prefab components before assigning a loader fault; normalize only extractor line endings and keep raw report bytes; require natural player exits and working fixture topology; initialized components, output filters and bounded charge witnesses matter; event cleanup must preserve pending heartbeat work and future command-buffer events; Mac app-root runtime status, startup readiness and actual restore witnesses.
- [Cross-machine built-player gameplay acceptance](memories/cross-machine-built-player-gameplay-acceptance.md) — (the gate behind Ben's standing rule above) a multiplayer gameplay fix requires matching current built players on two physical machines, Windows/macOS when affected, the reported sequence through real inputs, both-peer screenshots actually inspected, temporal evidence for motion, and an unweakened all-25-field typed comparison over the whole shared heartbeat window; direct IP does not prove Steam paths, and Windows GUI players launched over SSH may need a task-scoped launch into the logged-in desktop session.
- [Live tutorial evidence and producer tests](memories/live-tutorial-evidence-and-producer-tests.md) — run the tutorial to completion without a fixed time cutoff, retain continuous and live evidence, test actual scheduled producers, and preserve reports through atomic verified transfer.
- [Built-player screenshot and pointer coordinates](memories/built-player-screenshot-coordinate-scale.md) — screenshot response dimensions can be downscaled and are not raw pointer coordinates; read the live native view before driving UI, and clear both preview entities and native blueprint allocations (live-verified fix).
- [Built-player native CUA input](memories/built-player-native-cua-input.md) — on the Mac player, choose the exact app path, re-query AX state, raise its current window with native CUA, and inspect fresh AgentControl previews; separate repeated keys by game frames; real `R` input is distinct from networked `rotate.abs` and forbidden local RED injection.
- [Built-player boot hang and harness waiters](memories/built-player-hang-and-harness-waiters.md) — a shell-launched player can stall at waiting-title-menu at 0.2% CPU (kill the path-verified PID, relaunch); the Claude harness kills run_in_background sleep-pollers under memory pressure, so long waits go through Monitor
- [The verdict script rejects whole reports on eviction/give-up records](memories/verdict-script-rejects-eviction-records.md) — `continuous_determinism_verdict.py` scans the WHOLE file, not the window, and re-checks the footer counters; compare a run that ended in a network drop by dropping exactly the records its own `reject_unhealthy_record()` rejects, correcting the footer, listing every dropped line, and ending closed-epoch windows one sample early; a forced resync is NOT unhealthy
- [The `asteroids` fingerprint is blind to depleted/untargeted asteroids](memories/asteroids-fingerprint-blind-to-depleted-asteroids.md) — it hashes only asteroids a station targets or a miner sources, so an exhausted asteroid leaves the set exactly while its deletion timing forks; proven live (073 f4-cp1: 16,776 shared hb, 0 mismatches, while the peers disagreed for ~1,100 hb on whether it existed). A green hash over a KNOWN entity-set change is a blind-spot finding — poll the entity set directly, then widen the owning surface; widened at `4dc66303e` and LIVE-PROVEN positive 2026-09-16 (h1: `asteroids` the only mismatching field at the deletion heartbeat, detector verdict + recovery)
- [Multiplayer-dev player builds from the unity CLI shim](memories/unity-cli-mpdev-build-recipe.md) — **channel removed in w533 (use `scripts/unity-bridge.py`); history only** — no `--json` flag; `filter_type=testName|assembly|category`; call `BuildAllMultiplayerDevNoUpload` by reflection in a guarded update callback (the platform entry points skip localization + cicd copy); the no-version-update path leaves `PlayerSettings.bundleVersion` stale — eval it first; a platform-switch build can take ~140 min on shader-graph reimport; never `rebase --autostash` mid-build
- [Judge a build by its marker and child processes, not the editor's CPU](memories/judge-a-build-by-marker-and-children-not-editor-cpu.md) — during a build both editor channels time out and the editor process can sit at ~1% (Bee/IL2CPP are children): marker mtime + `pgrep -P <editor pid>` + Editor.log growth are the signals; the log may have rotated to `Editor-prev.log` when another editor started
- [Parameter-tail edits hit two methods; judge a compile by Csc marker order](memories/parameter-tail-edits-hit-two-methods-and-csc-marker-order.md) — `CreateGroupEntities`/`WriteGroupData` share a parameter tail (CS7036); `grep -c` the new symbol after any scripted signature edit; a failed compile keeps the last-good DLL while the log tail shows OLD errors — read only after the last Csc marker, then DLL mtime + `Type.GetType` on every editor
- [Recording clips on BEAST: no desktop frames, and two slot-pool launch traps](memories/beast-clip-capture-and-slot-launch-traps.md) — `record_clip`'s desktop capture can hang with a 0-byte file (display asleep, or another agent's fullscreen player): record the game's own frames with `-ffFeelFrames` and assemble them by `frames.csv`; `-ffSoloNewGame` for single player; fly a remote ship back across the view before its dash; never pass a slot's own folder to `player_slots.py launch`; `--detach` piped to `tail` never returns; a cold player build took 46 minutes; a Windows Firewall prompt dims every desktop recording; Gemini needs zoomed crops for HUD text and small ships; a warm build from the running editor takes minutes; a clip with sound needs a `-ffFeelLoad` single-player load (automation roles mute FMOD) and per-process audio capture (`proc-tap`), cut on the shared QPC clock
- [A branch switch under a booting editor can leave a stale assembly](memories/stale-assembly-after-branch-switch-under-booting-editor.md) — the previous branch's tests fail on develop code while CI is green; `FFSystems.dll` was compiled as the checkout landed and a forced refresh does not rebuild it (same content): compare the DLL's time with the file's, then change the content, compile, revert, compile
- [Verifying a UI gesture on video: virtual mouse, topmost clips](memories/ui-gesture-verification-virtual-mouse-and-topmost-clips.md) — a virtual Input System `Mouse` + `QueueStateEvent` drives the real `InputSystemUIInputModule` (clicks, drags) in the editor, which the ffauto pointer cannot; Esc/right-click still go through `InputHelper`/`AutomationPointer`; `record_clip --unity` records whatever window is on top, so keep the sandbox editor topmost while it records and check a contact sheet; the 10 fps blind model review cannot see a double-click and invents UI faults
- [Paired audit chains race across peers](memories/paired-audit-chains-race-across-peers.md) — host and client post-ready chains start on their own clocks and `ffauto:wait` offsets raced (green run, every op refused); use `movement.hold` for the offset (also feeds the `playerSimPos` liveness gate), never reuse a `--label`, prefer an ffnightly scenario with per-step peers and `poll`/`equals` on `observe.state` (`data.data.<field>`); the fingerprint does not cover `ResearchState`
- [After the branch is pushed, merge develop in; do not rebase](memories/no-force-push-means-merge-not-rebase-after-push.md) — a second rebase needs a force-push, which is forbidden; `git reset --hard ORIG_HEAD` then merge; the `CommandTiersTest` golden + generated ffauto reference conflict recipe; heredoc-apostrophe and worktree `info/exclude` shell traps
- [The paired audit compares only the last ~2,600 heartbeats](memories/paired-audit-compares-only-the-last-2600-heartbeats.md) — the dwell runs after the chain, so a long dwell leaves only idle time in the window (`FAIL [playerSimPos]: only 1 distinct value`); dwell 20000/12000 ms, chains under about 140 s, `wait|25` first on the host; a 12,000-character `--host-cmd` never launches the host; `--host-preconnect-cmd` does not hold the client back
- [A soft-reset squash reverts whatever merged since your rebase](memories/soft-reset-squash-reverts-what-merged-since-the-rebase.md) — `git reset --soft origin/develop` after develop moved put #888's revert into the squashed commit; reset to `git merge-base HEAD origin/develop`, then rebase, then read `git show --stat` before pushing; recover on a new branch name (no force-push, no remote delete in a sandbox)
- [A Mac built player of a branch: the M3 lab clone](memories/mac-player-of-a-branch-on-the-m3-lab-clone.md) — CI builds osx only on a release; `build_player.sh` in `~/nevergames/ff-nightly/FinalFactory` builds a commit in 8 min and the paired audit runs there; stop your sandbox editor before a remote `git checkout`; put the clone back and delete your build
